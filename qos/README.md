# 模型服务质量评测

网关记录每个请求的开始时间、首个 Token 时间、结束时间、Token 数、处理节点和成功与否。管理界面「服务质量」页面按模型和节点汇总这些记录，网页「压测」由网关内置功能发起

本目录提供独立的命令行性能压测和回答质量评测脚本，使用 [evalscope](https://github.com/modelscope/evalscope) 1.14.0，通过网关发送请求。运行这两个脚本需要 `litellm-qos-bench:evalscope-1.14.0` 镜像

## 指标含义

| 指标 | 计算方式 |
| --- | --- |
| 成功率 | 成功请求数 / 总请求数 |
| 峰值并发 | 同一时刻正在处理的请求数最大值 |
| 每秒请求数 (QPS) | 请求数 / 首个请求开始到最后一个响应结束的时长 |
| 输出 Token/秒 | 成功请求的输出 Token 总数 / 同一时长 |
| TTFT | 首个 Token 时间 - 请求开始时间，仅统计流式请求 |
| TPOT | (结束时间 - 首个 Token 时间) / (输出 Token 数 - 1)，仅统计流式请求 |
| 总延迟 | 结束时间 - 请求开始时间 |

页面显示 P50 / P95，接口 `/qos/summary` 同时返回 P99。缓存命中的请求不计入统计。TTFT、TPOT 不统计语音、图像和视频请求

## 语音和视频

语音合成、语音识别和视频请求的服务指标显示在「服务质量」页面的「音视频」标签页，按模型汇总，页面显示 P50 / P95。接口 `/qos/media` 返回同样的数据并包含 P99，时间范围参数与 `/qos/summary` 相同

| 模态 | 指标 | 计算方式 |
| --- | --- | --- |
| 语音合成、语音识别 | 耗时 | 成功请求的结束时间 - 请求开始时间 |
| 语音合成、语音识别 | 实时率 (RTF) | 耗时 / 音频时长，小于 1 表示比实时快。音频时长：合成取返回音频的文件头，识别取上传音频的长度 |
| 语音合成 | 有效字数 | 输入文本去掉标点、空白后的字数 |
| 视频 | 提交、成功、失败、取消 | 按任务计数，同一任务的多次查询只算一次 |
| 视频 | 暂无结果 | 已提交但还没有查询到结束状态的任务数 |
| 视频 | 排队时间、生成时间 | 服务商任务记录里的 开始时间 - 创建时间、完成时间 - 开始时间，只统计成功的任务的生成时间 |
| 视频 | 价格 | 服务商任务记录里的价格合计 |

这些数据记在每个请求的 SpendLogs `metadata.qos_media` 里。代理层直接拒绝的失败请求没有调用类型，按部署配置的 `model_info.mode`（`audio_speech`、`audio_transcription`、`video_generation`）归类，所以音频、视频模型要设好 `mode`

## 准备

构建压测镜像，只需执行一次

```bash
docker build -t litellm-qos-bench:evalscope-1.14.0 qos
```

两个脚本按需启动临时容器，运行结束后自动删除容器并保留镜像。因此，没有容器使用这个镜像时，它仍可供下次评测直接使用

只使用网页压测时，可以删除这个镜像以节省磁盘；下次使用命令行脚本前，按上面的命令重新构建。评测报告保存在宿主机的 `qos/results/` 目录，网关历史记录保存在 PostgreSQL 数据卷，删除评测镜像会保留这些数据

建议在管理界面为压测单独创建一个虚拟密钥，并设置为环境变量

```bash
export LITELLM_API_KEY=sk-...
```

网关默认地址为 `http://host.docker.internal:4000`，其他地址通过 `LITELLM_BASE_URL` 指定

## 并发与性能压测

依次在每个并发数下发送流式请求，提示词来自 `prompts.txt`，每行一条

```bash
./qos/run-perf.sh qwen3-max 1 4 16 32
```

每个并发数发送「并发数 × 8」个请求，可用 `QOS_REQUESTS_PER_WORKER` 调整，最大输出 Token 默认为 512，可用 `QOS_MAX_TOKENS` 调整

脚本结束时打印本次的请求标签，例如 `qos-20261023-001747-qwen3-max`。在「服务质量」页面填入该标签并刷新，即可只看这一轮压测，展开模型行可对比各节点。evalscope 的客户端报告保存在 `qos/results/<标签>/`

## 回答质量评测

使用标准数据集评测模型回答，数据集在首次运行时从 ModelScope 下载

```bash
./qos/run-eval.sh qwen3-max gsm8k ceval
```

每个子集默认取 50 条，可用 `QOS_EVAL_LIMIT` 调整。数据集名称见 evalscope 文档，报告保存在 `qos/results/eval-*/reports/`

## 注意事项

- TTFT 和 TPOT 只能从流式请求得到，非流式请求只统计总延迟
- 网关以多个 worker 运行且未配置 Redis 时，限流和节点健康状态在各 worker 内分别计算。高并发压测前建议配置 Redis，或直接对节点压测一次作为对照，避免网关成为瓶颈
- 统计数据来自网关的请求日志，写入数据库有数秒延迟，压测结束后稍等再刷新页面
