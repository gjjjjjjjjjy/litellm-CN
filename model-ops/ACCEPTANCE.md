# 验收标准与方法：图像、音频、视频

2026-10-23 起草。适用于模力方舟（Gitee AI）上跑在沐曦卡上的生成类模型，分两种场景：一是新模型上线验收，二是迁移等价验收（C500 换 C600，或换推理框架、换镜像、从别家卡搬到沐曦）。两种场景都按功能、质量、性能、稳定性四层检查，迁移场景再加一层「和迁移前是否等价」

文中的门槛凡是标「建议初值」的，都是本文提出的起点，不是业界统一标准。生成模型的跨硬件等价目前没有公认的公开门槛，这些数要在第一次真实迁移时用实测数据校准，校准方法见各节

## 一、所有模态都要遵守的规则

**迁移前先冻结基线。** 模型搬走以后，旧硬件上的输出就再也拿不到了，所以基线必须在迁移之前采集：固定提示词或文本、固定 seed、所有参数显式写出（不依赖平台默认值，默认值以后可能改）。2026-10-23 实测，模力方舟上 Qwen-Image-2512 同一请求重复两次，输出的 PNG 逐字节相同（`results/baselines/smoke-20261023/manifest.jsonl`），说明当前部署是确定性的，迁移后出现的任何差异都来自这次变更

**锁定算力。** 同一个模型在模力方舟上可能同时挂在几家的卡上（例如 z-image-turbo 是昇腾加沐曦，flux-1-schnell 是壁仞加沐曦），不少接口还有 `X-Failover-Enabled` 参数，默认开启时沐曦出错会悄悄切到别家。验收时要做到三点：用只绑定沐曦算力的 key（我们现在这把 key 调不了只在百炼、燧原上的模型，调得通的都在沐曦上）；把 `X-Failover-Enabled` 设为 false；多家共用的模型如果没法从公网接口指定算力，就向 Gitee.AI 要能看出服务节点的响应头，或者在内部直连沐曦的地址上测

**判官不变。** 用来打分的模型（ASR、CLIP、偏好打分模型）在迁移前后必须是同一个版本、同一个地址，否则分数变化可能来自判官本身。Whisper 当判官时 `temperature` 设 0（模力方舟默认 0.7）

**参数逐个确认生效。** 不同模型的参数名不统一：步数有 `num_inference_steps` 和 `steps` 两种，引导强度有 `guidance_scale` 和 `cfg_scale` 两种。传错的名字会被静默忽略，平台不报错（之前 `json_schema` 和 `guided_json` 都踩过这类坑）。新上线时要把每个对外参数改一次，确认输出跟着变；迁移时确认参数表没被改（`tools/moark_inventory.py` 会报出参数变化）

**三层判定。** 先跑自动指标，过了门槛直接算通过；没过门槛的样本由人看；差异大或者人拿不准的，做盲评 A/B。结论只有三种：通过、有条件通过（写明条件）、不通过。每次验收都要留证据目录：请求、原始输出、指标、人工意见

## 二、图像（文生图、图像编辑、放大、抠图）

### 2.1 范围

截至 2026-10-23，沐曦 Token 资源包（1492）里跑在沐曦上的图像模型有 11 个，完整清单和每个模型的接口参数见 `models/IMAGE_MODELS.md`。其中 Kolors 的文生图、垫图、风格迁移，以及 SD3.5-large-turbo，接口不暴露 seed，只能做按组比较

### 2.2 功能

| 检查项 | 方法 | 通过标准 |
|---|---|---|
| 尺寸与格式 | 每个尺寸档（1024、1536、2048）各出一张，读文件头 | 宽高等于请求值，能正常解码 |
| seed 可复现 | 同一请求连发两次 | 两次输出逐字节相同。不相同就说明部署里有非确定性，后面的逐张对比要改成按组比较 |
| 参数生效 | 步数、引导强度、负向提示词各改一次 | 输出随之变化；负向提示词用例 `negative_ramen` 画面里不出现筷子、勺子 |
| 同步与异步 | 有异步接口的模型各跑一次 | 异步任务能取回结果，`created_at`、`started_at`、`completed_at` 齐全 |
| 错误处理 | 超出范围的尺寸、空提示词、超长提示词 | 返回明确的 4xx 和错误信息，不返回空图或黑图 |
| 非 16 倍数尺寸 | 接口里有的 `1024x683` 这类选项 | 返回的图尺寸和请求一致或有明确说明；不报 500（FLUX 会悄悄缩放，Z-Image 会报错） |
| 编辑类 | 图生图、局部重绘、风格迁移、人脸迁移各一例 | 输出尺寸正确，编辑区域生效，未编辑区域基本保持 |

### 2.3 质量（新模型上线时）

质量要和一个参照比：同一模型的官方部署或 NVIDIA 参考部署，或者被替换的旧版本。检查用固定提示词集 `testsets/image_prompts.json`（16 条，覆盖中英文文字渲染、计数、空间关系、手、复杂场景、渐变和暗部等精度探针）

| 检查项 | 方法 | 通过标准（建议初值） |
|---|---|---|
| 中文文字渲染 | OCR 读出图中文字，和提示词里的引号内容比对 | 2 条中文用例全部字字正确；比参照少对 1 条以上就不通过 |
| 提示词遵循 | 计数、空间、长提示词三类按 `check` 字段逐项打勾 | 不低于参照 |
| 画面缺陷 | 人看：手、脸、肢体、文字、格纹、色带、暗部噪点 | 不出现参照没有的新缺陷类型 |
| 偏好分 | HPS / ImageReward / PickScore 等打分模型（需要 torch，计划中） | 平均分不低于参照 1 个标准误以上 |

### 2.4 迁移等价（最重要）

**有 seed 的模型逐张比。** 用 `tools/image_baseline.py` 在迁移前后各采一次（同提示词、同 seed、同参数），再用 `tools/compare_images.py` 逐张算 PSNR 和 SSIM：

| 结果 | 判定（建议初值） | 处理 |
|---|---|---|
| 逐字节相同 | identical | 通过 |
| SSIM ≥ 0.98 且 PSNR ≥ 35 dB | same | 通过 |
| 0.90 ≤ SSIM < 0.98 | close | 人看差异图，没有新缺陷就通过 |
| SSIM < 0.90 | different | 必须人工复核，并做盲评 |

**先判断随机数序列有没有变。** 同 seed 能不能逐张比，取决于新旧环境生成的初始噪声是否相同。公开测试里，两个后端随机数序列不同时，同 seed 出的图毫无关系（FlagOS 实测 Qwen-Image-2512 跨后端 PSNR 9.5 dB）；初始噪声对齐以后，Qwen-Image-2512 50 步约 35.4 dB，Qwen-Image-2.1 40 步约 37.8 dB；哪怕只有 0.0045% 的元素差一个最小精度单位，50 步后也会掉到 28.6 dB（https://github.com/flagos-ai/torch-fl 的 `tests/manual/qwen_image_2512`、`qwen_image_21`）。换 C600 至少要升到 MACA 3.7、torch 也会换版本（见 `models/IMAGE_MODELS.md`），随机数序列可能变。判断方法：看 `flat_gradient` 和 `landscape_mist` 两条的同 seed 对比，构图一致、PSNR 在 20 dB 以上，说明噪声相同，按上表逐张比；构图完全不同、PSNR 在 15 dB 以下，说明噪声变了，逐张指标没有意义，改用下面的按分布比较

**噪声相同时。** 细小的算子差异会在几十步采样里放大，同 seed 出来的图构图一样但细节不同，SSIM 落到 0.7 到 0.9 也不一定是错。所以 SSIM 低本身不判不通过，判不通过要满足下面任一条：盲评里旧版明显更好（见第五节的判定表）；出现旧版没有的缺陷（全黑、全白、格纹、色带、文字错字）；精度探针 `flat_gradient`、`low_light` 出现色带或彩色噪点

**噪声变了时，按分布比较。** 每个模型用全部 16 条提示词乘 2 个 seed，比整组的 CLIPScore 平均值（提示词遵循），加中文文字 OCR 正确数和盲评。建议初值：CLIPScore 平均值下降不超过 2%（相对值）。这个数参照的是 FlagRelease 对 Qwen-Image-2.1 的跨平台对齐结果：NVIDIA 原版在 T2I-100 上 33.66，沐曦 33.75、昇腾 33.31、NVIDIA FlagOS 版 33.26，COCO 上 25.34 对 25.11 到 25.76，它们都声称「已与官方对齐」，相互差在 ±2% 以内（https://huggingface.co/FlagRelease/Qwen-Image-2.1-BF16-metax-FlagOS）。FlagOS 对大模型用的规则是新旧得分差不超过 5%，对扩散模型没有公开门槛，沐曦 modelzoo 的 `--eval` 也只报 CLIP 分不设门槛。CLIPScore 需要 open_clip 和 torch，`compare_images.py` 还没加（计划中），在加上之前先靠 OCR、粗统计和盲评

**门槛怎么校准。** 第一次迁移前，先拿两组「已知等价」的数据定出正常波动范围：同一硬件隔一周重采一次（应当逐字节相同，不同就说明平台悄悄改了东西）；多家共用的模型如果能拿到不同厂商卡上的输出，它们之间的差异就是「跨硬件正常漂移」的参考值。迁移后的差异落在这个范围内算正常

**没有 seed 的模型按组比。** 同一提示词采 2 次以上，比较整组的亮度、饱和度、清晰度分布，以及全黑、全白张数（`compare_images.py` 已实现），再加盲评。判定标准：分布没有明显偏移，盲评不劣于旧版

**部署配置要一并核对。** 迁移经常顺带换镜像，配置可能被改掉。要核对的有：上游模型版本（sha）、步数和引导强度的默认值（例如模力方舟上 Qwen-Image-2512 默认 4 步、cfg 1，和 lightx2v 的 Lightning 4 步版一致，迁移后要保持）、加载的 LoRA 和版本、调度器和 sigma 列表、精度（BF16 还是量化）、diffusers 和 transformers 版本（升级可能改变参数含义，例如 Z-Image 的步数）。现网默认值和官方推荐不一致的地方已整理在 `models/IMAGE_MODELS.md`

### 2.5 放大与抠图

Real-ESRGAN 和 RMBG-2.0 都是确定性模型，没有采样随机性，迁移前后的输出应该几乎一样。放大：输出尺寸等于输入乘以倍数，和迁移前输出比 SSIM ≥ 0.99（建议初值）。抠图：alpha 通道逐像素比，平均绝对差 ≤ 1%（建议初值），边缘区域另看。要和公开数据集对比时，抠图用 SAD、MSE、Grad、Conn（MIT 许可的实现有 GCA-Matting 和 P3M 的 `evaluate.py`），放大用 PSNR、SSIM、LPIPS、DISTS。注意常用的 pyiqa 库代码是 PolyForm Noncommercial 许可，权重是 CC BY-NC-SA，公司内部验收不宜直接用

### 2.6 性能与稳定性

| 检查项 | 方法 | 通过标准（建议初值） |
|---|---|---|
| 延迟 | 1024² 和 2048² 各 20 次，记端到端时间和响应头 `X-Compute-Time` | P50 不比迁移前慢 10% 以上；P95 不比迁移前慢 20% 以上 |
| 排队 | 异步接口记 `started_at - created_at` | 空闲时段 P95 < 5 秒 |
| 成功率 | 连续 200 次请求 | 失败率 < 1%，失败都有明确错误码 |
| 最大尺寸 | 每个模型最大档连发 10 次 | 不出现 OOM 或超时 |

10-23 已观察到同一请求服务端计算时间一次 7.3 秒、一次 29.1 秒，说明现网延迟波动大，比较延迟要用多次采样的分位数，不能只看一次

## 三、音频（语音合成、语音识别、音乐）

### 3.1 范围

截至 2026-10-23，资源包里跑在沐曦上的音频模型只有 SenseVoiceSmall、whisper-large-v3-turbo（语音识别）和 IndexTTS-2（语音合成，默认开着切到燧原的 failover）。其余 TTS 在燧原、壁仞、昇腾、Gitee 自有卡和 TeleAI 上。将来搬到沐曦时，沐曦公开验证过的只有 Qwen3-TTS（vllm-omni-metax 0.26，已有 C600 高并发配置）

TTS 和图像最大的不同是：大多数 TTS 是自回归采样，模力方舟上只有 CosyVoice3 和 ACE-Step 暴露 seed，所以迁移等价只能比指标分布，不能逐条比

### 3.2 功能

| 检查项 | 方法 | 通过标准（建议初值） |
|---|---|---|
| 格式 | 读采样率、声道、编码 | 与文档一致（Qwen3-TTS、CosyVoice3 为 24 kHz） |
| 时长合理 | 有效字数除以时长 | 中文每秒 3 到 8 字；明显偏离说明漏读、重复或拖长 |
| 首尾静音 | 10 ms 帧能量，阈值 -45 dBFS | 首尾各 < 0.8 秒；结尾突然截断（ASR 少最后几个字）判不通过 |
| 削波与响度 | 峰值、削波比例、ITU-R BS.1770 响度 | 削波比例 < 0.1%；响度在 -26 到 -14 LUFS 之间，迁移前后相差 ≤ 2 LU |
| 声音克隆 | 用参考音频加参考文本合成 | 能听出是同一个人；SIM 分数见 3.3 |
| 克隆缓存串音 | 同一个音色名先后换两段不同参考音频（例如先英文后中文）各合成一次 | 第二次必须用新参考音频。vllm-omni-metax 修过这个 bug：缓存按音色名而不是参考音频记，旧缓存混上新文本时模型不停止，输出约 40 秒乱码 |
| 情感与风格控制 | IndexTTS-2 的音频控制和文本控制各一例，CosyVoice3 的 instruct 一例 | 听得出控制生效 |
| 极短与长文本 | `very_short`（2 个字）和 `long_paragraph`（约 190 字） | 极短不报错、不出长静音；长文本不截断、结尾不乱码 |
| 数字、多音字、中英混读 | `tts_texts.json` 里对应用例 | 人听判对错（这类用例不算 CER，读法有多种正确形式） |
| 流式 | 有 WebSocket 或流式接口的模型 | 记首包时间；流式和非流式内容一致 |

### 3.3 质量

**可懂度用 CER。** 合成音频送进固定的 ASR 判官，转写结果和输入文本比，算字错率。比之前两边都去标点，并用 cn2an 统一数字写法（SenseVoice 会把「二十三」写成「23」，不统一会被误判成错字）。`tools/audio_eval.py check` 已实现，判官默认用模力方舟上的 SenseVoiceSmall：它是非自回归 CTC 贪心解码，同一段音频每次结果一样，跑在沐曦上，免费。对外报数要和论文可比时，按 seed-tts-eval 的做法用 Paraformer-zh 算中文 CER、Whisper-large-v3 算英文 WER，但 `paraformer-zh` 这个名字从 ModelScope 和 HF 下载会拿到两个不同的模型，要写死模型 id 和 sha。不要用 Fun-ASR-Nano 这类 LLM 解码的 ASR 当判官，它的语言先验可能把读错的地方纠正回来。各判官对比见 `models/AUDIO_MODELS.md`

**音色相似度用 SIM。** 参考音频和合成音频分别过说话人验证模型取向量，算余弦相似度（seed-tts-eval 用 WavLM-large 微调的说话人模型）。需要 torch，计划中

**自然度用 MOS。** 自动预测用 UTMOS 一类模型（计划中），人工用 5 分制 MOS 或新旧对比的 CMOS，小规模内部评审每条至少 3 人

| 指标 | 新上线通过标准（建议初值） |
|---|---|
| CER（可计分的 13 条） | 平均 ≤ 3%，单条 ≤ 10%；不高于该模型论文公布值加 1 个百分点 |
| SIM | 不低于论文公布值减 0.03 |
| MOS | 不低于参照 0.2 分以上 |

### 3.4 迁移等价

没有 seed 的 TTS：每条文本迁移前后各合成 3 次，比较平均值

| 指标 | 通过标准（建议初值） |
|---|---|
| 平均 CER | 升高 ≤ 1 个百分点（绝对值） |
| 失败条数（报错、无声、截断） | 不增加 |
| 平均时长 | 变化 ≤ 5% |
| 响度 | 变化 ≤ 1 LU |
| SIM（有了以后） | 下降 ≤ 0.02 |
| 盲评 CMOS | 新版不明显差于旧版（第五节判定表） |

有 seed 的（CosyVoice3、ACE-Step）先试同 seed 是否逐字节可复现，可复现就逐条比，再按上表兜底。自部署的 vllm-omni 接口有 `seed` 字段，在内部地址上测时可以固定

语音识别模型本身迁移：解码设成确定性（`temperature` 0），用同一批测试音频比，转写结果应该基本一致，CER 变化 ≤ 0.2 个百分点（建议初值）

### 3.5 性能

记端到端时间、`X-Compute-Time`、实时率（生成耗时除以音频时长）和流式首包时间。迁移后 P50 不比迁移前慢 10% 以上（建议初值）

## 四、视频（文生视频、图生视频、音视频联合、数字人）

### 4.1 范围

截至 2026-10-23，沐曦上有 LTX-2（图生视频）、MiniMax-H3（文生视频、首尾帧生视频、参考生视频，壁仞加沐曦）、Wan2_2-I2V-A14B（图生视频，壁仞加沐曦）。三个都走异步接口（`v1/async/videos/...`），都暴露 seed

### 4.2 功能

| 检查项 | 方法 | 通过标准 |
|---|---|---|
| 规格 | ffprobe 读时长、帧率、分辨率、帧数、编码 | 等于请求值（LTX-2 默认 73 帧 24 fps 512×512；Wan2.2 默认 33 帧 832×480） |
| 首帧一致（图生视频） | 第 0 帧和输入图算 SSIM | ≥ 0.85（建议初值） |
| 尾帧一致（首尾帧） | 最后一帧和输入尾帧比 | ≥ 0.85（建议初值） |
| 音轨（MiniMax-H3） | 有没有音轨、声道、采样率 | 有立体声音轨，时长和画面一致 |
| 异步流程 | 提交、轮询、取回 | 三个时间戳齐全，结果文件能下载 |

### 4.3 质量

人工每条视频回答三个问题：画面有没有崩坏（肢体、物体结构）；有没有闪烁或跳变；和提示词是否一致。自动指标可以用 VBench 的部分维度（主体一致性、背景一致性、运动平滑度、时间闪烁、画质），需要 GPU，计划在沐曦或 NVIDIA 机器上跑。MiniMax-H3 要额外听开头 0.5 秒有没有乱码或截断（上游已知问题），有人说话的视频看口型同步

### 4.4 迁移等价

和图像一样，同 seed 迁移前后各生成一次。每秒抽 1 帧逐帧算 SSIM，再看首帧一致性有没有变差、帧数和时长有没有变。帧级差异的判定沿用 2.4 的思路：差异大不直接判错，以盲评和新缺陷为准。视频单条成本高（Wan2.2 每条 ¥1.5），建议每个模型 8 条提示词乘 1 个 seed

### 4.5 性能

每 5 秒视频的生成时间、排队时间、成功率。迁移后生成时间不比迁移前慢 15% 以上（建议初值）

## 五、人工评审怎么做

盲评 A/B：`compare_images.py` 会生成 `blind.html`，每对图左右顺序随机，评审只选「左好」「右好」「看不出差别」，答案在 `blind_key.json`。音频、视频照同样方法做

判定用单侧符号检验（只数有偏好的票，看不出差别的不计）：

| 有偏好的票数 | 旧版胜出达到这个数，就判新版明显更差 |
|---|---|
| 10 | 9 |
| 20 | 15 |
| 30 | 20 |
| 50 | 32 |
| 100 | 59 |

显著性水平 0.05。看不出差别的票占多数本身就是好结果，说明迁移没有带来可察觉的变化

## 七、一次迁移的完整流程

1. 迁移前：跑 `moark_inventory.py` 记录当前算力；用 `image_baseline.py` 采集图像基线（8 个模型 × 16 条 × 2 个 seed，256 张，约 ¥14）；采集 ASR 固定音频的转写；按预算采集 TTS 和视频样本
2. 迁移中：盯 `moark_inventory.py` 的算力变化，和 Gitee.AI 确认切换时间
3. 迁移后：用同样的参数重采，跑对比脚本，人看差异样本，必要时盲评
4. 结论写进 `results/` 下的对比报告，有问题按 `feedback/TEMPLATE.md` 提单，复测通过后关单
